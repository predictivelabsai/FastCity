# FastCity

**FastCity** is an open-source **smart-city IoT data platform** built with
[FastHTML](https://fastht.ml) — a server-side, HTMX-driven analytics &
management layer for a city sensor estate. Python-first, no JavaScript
framework: a **device registry** (pasportization), **telemetry ingestion** +
time-series **dashboards**, **threshold alarms**, low-code **data flows**, and
an AI assistant grounded in your live telemetry.

*The city's sensors, in one honest data layer.* Runs on port **5011**.

> **Synthetic data only — no PII.** Everything ships and runs on deterministic,
> fully synthetic sensor/telemetry data generated by `seed.py`.

## What FastCity is (and isn't)

FastCity is the **data / analytics / management layer** — the part we actually
own and ship: registry, telemetry store, dashboards, alarms and an open
ingestion API. It is deliberately **honest about scope**:

- ✅ **Device registry**, **telemetry store**, **dashboards**, **alarms**, **AI query**, **open ingestion API**.
- 🔌 **Integration surface, not a broker.** The connector runtime (MQTT / MODBUS /
  REST / CoAP) is represented as **config-defined "flows"** and a single
  ingestion endpoint — it is **stubbed**, not a carrier-grade middleware bus.
- 🧩 **Composes, no vendor lock-in.** Point [FIWARE](https://www.fiware.org/),
  [ThingsBoard](https://thingsboard.io/) or [Node-RED](https://nodered.org/) at the
  ingestion API for the full bus; FastCity stays the open, queryable data layer.

## Quickstart (native)

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.sample .env          # optional — add an LLM key for free-form AI chat
.venv/bin/python web_app.py  # http://localhost:5011  (self-seeds on first boot)
```

Login: `admin@fastcity.example` / `FastCity2026$` (override in `.env`).
Rebuild demo data: `.venv/bin/python seed.py`.

## Run with Docker

```bash
docker compose up --build      # http://localhost:5011
```

`Dockerfile` (python:3.12-slim, port 5011) seeds on first boot;
`docker-compose.yml` mounts a `fastcity-data` volume at `/data` so the SQLite
DB survives rebuilds.

## Module tour

- **Dashboard** (`/`) — city KPIs (devices, live sensors, down, active alerts),
  per-domain live average with sparklines, device-status breakdown, alert worklist.
- **Device Registry** (`/devices`) — the sensor "pasportization": asset code,
  domain, zone, geolocation, firmware, last-seen. Open a device for its **72h
  telemetry chart** and recent readings.
- **City Map** (`/map`) — every sensor plotted by lat/lng in a **self-contained
  SVG** map (no tile server needed; Leaflet/MapLibre-ready coordinates).
- **Domain Dashboards** (`/dashboards`) — **Plotly** time-series of the 72h city
  average per domain (traffic · parking · environment · energy · waste · noise),
  with the alarm threshold drawn in.
- **Alarms & Alerts** (`/alerts`) — threshold **rules**
  (`domain · operator · value · severity`) evaluate each sensor's latest reading;
  add rules, run evaluation, acknowledge / resolve the alerts raised.
- **Data Flows** (`/flows`) — low-code, **config-defined integration pipelines**
  (MQTT / MODBUS / REST / HTTP / CoAP) — the integration surface (stubbed runtime).
- **Ingestion API** (`/ingest`, `POST /api/telemetry`) — the open write path
  connectors call to push readings (JSON, no vendor lock-in).
- **AI Assistant** (right rail) — chat over a **live snapshot** of the telemetry.
  Plain-English questions stream from a configurable LLM provider; **slash-commands**
  (`/kpi`, `/devices`, `/domain`, `/alerts`, `/rules`, `/help`) resolve instantly
  with **no API key**.

## Telemetry ingestion API

The open write path any connector calls to push a reading:

```bash
curl -X POST localhost:5011/api/telemetry \
  -H 'Content-Type: application/json' \
  -d '{"device_id": 1, "value": 42.0}'
# → {"ok": true, "device_id": 1, "value": 42.0, "stored": "..."}
```

`ts` is optional (`"YYYY-MM-DD HH:MM:SS"`); it defaults to now.

## Domains & alarms

Six IoT domains ship with synthetic diurnal telemetry and a default "high"
threshold rule each:

| Domain | Metric | Unit | Default threshold |
|--------|--------|------|-------------------|
| Traffic | Vehicle flow | veh/min | > 80 |
| Parking | Occupancy | % | > 90 |
| Environment | PM2.5 | µg/m³ | > 50 |
| Energy | Power draw | kW | > 120 |
| Waste | Bin fill | % | > 85 |
| Noise | Sound level | dB | > 70 |

Rules evaluate each sensor's latest reading; faulty sensors emit a spike that
trips their alarm so the demo shows a live alert list.

## Configuration

`.env` (see `.env.sample`). Free-form AI chat needs one provider:

```ini
MODEL_PROVIDER=xai          # xai | openai | anthropic | google
MODEL_NAME=grok-4-1-fast-reasoning
XAI_API_KEY=...
```

Without a key the whole app still works and slash-commands answer from SQLite.

## Architecture

```
web_app.py        routes, auth, ingestion API, SSE chat endpoint, boot
db.py             SQLite schema + domains + rule engine + read helpers
seed.py           deterministic synthetic sensor/telemetry generator
web/layout.py     3-pane shell, CSS, chat JS
web/views.py      page renderers (+ inline SVG charts / map)
web/ai.py         slash-commands + multi-provider streaming chat
static/           favicon
```
